# Forward Evaluation Matrix

Use this only when evaluating or evolving `skill-godot`, not as routine project guidance.

`tests/fixtures/craft-overhaul-coverage.json` is a focused six-case plan for UI comprehension, motion mechanisms and evidence admissibility. Its independent runs are explicitly unexecuted; runnable mechanism/validator tests must not be presented as those missing perceptual reviews.

Maintain one blind scenario per materially distinct contract and several deliberate hybrids. Give the builder only the user brief, installed skill and isolated workspace. Keep expected failures, proposed fixes and prior reviewer verdicts out of the build prompt. A separate context reviews raw target-build artifacts and uncoached traces.

Minimum suite: 2D, 3D third-person, fixed isometric, fixed/high-angle 3D district composition, architectural material direction and action camera, 2.5D, procedural roguelike, strategy/simulation, vehicle/racing, shooter/action, narrative, local multiplayer, online/extraction, mobile native, localized release, large-world streaming, replay and runtime authoring. Hybrid scenarios should include shooter+extraction+progression, high-angle district+action/extraction, procedural+strategy+save, narrative+localization, and mobile+store+liveops. The high-angle negative fixture must include a fully material-covered district whose random flood-fill/checkerboard assignment still fails, so coverage and hue counts cannot masquerade as art direction. Motion/delivery-proof coverage must include a valid decoded Godot MJPEG packet and a negative case where an existing AVI without decoded/inspected visual artifacts is incorrectly claimed as watchback. General production-motion coverage must separately include a complete normal-speed cause/contact/settle cycle plus dense repeated motion, and a negative fixture where valid tweens/endpoints still look unnatural, slide, miss contacts, synchronize mechanically, or mistime the reward.

Record skill commit, Godot version, scenario ID, builder/reviewer contexts, requested scope, applicable composite cases, first-pass outcome, user-found defects, gate that should have caught each defect, false-positive burden, tokens/time, and whether the correction belongs in instructions, a template, a deterministic tool, or the game itself. Never tune the skill to one screenshot without a reusable failure mechanism.

Use `assets/forward-eval-matrix.template.json` and `scripts/forward_eval_audit.py --mode coverage` to check declarations. Historical schema-v1 matrices are coverage plans only; their descriptive results do not count as executed evaluations. Use schema-v2 and `--mode execution` with actual hashed briefs/results and preserved response receipts to validate observed runs, following [evidence-integrity.md](evidence-integrity.md). A focused correction may use `scope=focused`; it needs meaningful positive/negative cases, not four artificial genre hybrids. A new contract remains provisional as a behavioral improvement until an actual task and independent review demonstrate it.
