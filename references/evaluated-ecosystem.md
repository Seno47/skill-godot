# Evaluated Godot Ecosystem Sources

Use this reference only when selecting a third-party template, addon, framework, shader, theme, or external skill. It is a dated review snapshot, not an allowlist and not a substitute for rechecking the exact release that will enter a game.

## Adoption rule

Do not merge a repository into a project because it appears in this catalogue. Before adoption:

1. Open the canonical upstream source and pin the inspected tag or commit.
2. Verify the exact license and bundled third-party notices for that revision.
3. Verify the declared Godot version against the project's actual editor version and renderer.
4. Inventory editor plugins, `@tool` scripts, autoloads, input actions, project settings, audio buses, custom resource/import types, native libraries, web scripts, and transitive dependencies.
5. Compare ownership with the existing project. Two save managers, input rebinders, scene loaders, audio managers, or platform bridges are a conflict even if both import cleanly.
6. Install into a disposable copy or minimal spike first. Import, run its representative scene, disable/re-enable the plugin, and test removal before touching the production project.
7. Adopt the smallest coherent surface. Prefer editable copied example scenes or a narrow addon over an entire framework when only one feature is needed.
8. Record the decision in `assets/addon-adoption-record.template.md`, including rejected alternatives and update/removal strategy.

Never execute downloaded code, enable an addon, accept marketplace terms, or replace project-wide architecture merely to inspect it. Aggregators and skill mirrors help discovery; their summaries do not replace upstream code, license, releases, or official platform documentation.

## Conflict priorities

When advice conflicts, apply this order:

1. The user's explicit brief and target platform.
2. The inspected project's existing architecture and supported Godot version.
3. Current official Godot/platform documentation and measured target-build behavior.
4. This skill's scene-first ownership and evidence gates.
5. A pinned third-party project's documentation for the exact adopted revision.
6. Aggregators, mirrors, examples, and generic genre numbers.

Examples are not universal laws: a fighting game does not always need rollback, direct-space hit queries, 60 rendered FPS, or a fixed 10% combo scale; a metroidvania does not need threaded room loading if measured transitions are already instant; every game does not need an ECS, reactive UI, or a monolithic menu suite. Record the choice and prove the relevant behavior.
